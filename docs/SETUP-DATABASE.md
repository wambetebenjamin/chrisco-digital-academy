# Reviving the database and turning on Google login

The app talks to **Supabase** for accounts and enrolments. Without the two
environment variables it runs in preview mode (browser storage), which is why
sign-in works locally but not as a real account system yet.

---

## 1. Why sign-in may be failing right now

Three separate things can cause it, in order of likelihood:

| Symptom | Cause | Fix |
| --- | --- | --- |
| "Supabase is not configured" / preview mode banner | `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY` are not set in the build environment | Add them to `.env.local` (local) and to Vercel → Project → Settings → Environment Variables, then redeploy |
| Project unreachable, requests hang or 5xx | Free-tier Supabase projects **pause after about 7 days of inactivity** | Open the Supabase dashboard → project → **Restore project** (takes a few minutes). Nothing is lost; the data stays intact |
| "Invalid login credentials" for an existing account | Email confirmation was never completed, or the user was created before email confirmation was turned off | Confirm the email from the inbox, or Authentication → Users → confirm manually. For testing, Authentication → Providers → Email → turn **Confirm email** off |
| Sign-up succeeds but no session | Email confirmation is on (correct for production) | User must click the link in the email before signing in |

Check the browser console after a failed attempt. Supabase errors are explicit
(`Invalid API key`, `Email not confirmed`, `User not found`).

## 2. Restore the project

1. Go to <https://supabase.com/dashboard> and sign in.
2. If the project shows **Paused**, click **Restore project** and wait for the
   status to return to **Active**.
3. Open **Project Settings → API** and copy:
   - `Project URL` → `NEXT_PUBLIC_SUPABASE_URL`
   - `anon public` key → `NEXT_PUBLIC_SUPABASE_ANON_KEY`
4. Add them locally:

```bash
# .env.local
NEXT_PUBLIC_SUPABASE_URL=https://YOUR-PROJECT-REF.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGciOi...
```

5. Add the same two values in **Vercel → Settings → Environment Variables** for
   Production, Preview and Development, then redeploy. Without this, the live
   site keeps using preview mode.

Once the keys are present the app switches to real Supabase auth automatically,
and the preview-mode banner disappears from the sign-in screen.

## 3. Database tables

Run this once in **Supabase → SQL Editor → New query**. It is safe to run on an
existing database: `if not exists` guards and idempotent policies are used.

```sql
-- Profiles, one row per auth user
create table if not exists public.profiles (
  id uuid primary key references auth.users on delete cascade,
  name text,
  email text,
  ref text,
  created_at timestamptz default now()
);

-- Enrolments
create table if not exists public.enrollments (
  id bigint generated by default as identity primary key,
  user_id uuid references auth.users on delete cascade not null,
  course_title text not null,
  created_at timestamptz default now(),
  unique (user_id, course_title)
);

alter table public.profiles enable row level security;
alter table public.enrollments enable row level security;

-- A user may only read and write their own rows
drop policy if exists "own profile read" on public.profiles;
create policy "own profile read" on public.profiles
  for select using (auth.uid() = id);

drop policy if exists "own profile write" on public.profiles;
create policy "own profile write" on public.profiles
  for insert with check (auth.uid() = id);

drop policy if exists "own profile update" on public.profiles;
create policy "own profile update" on public.profiles
  for update using (auth.uid() = id);

drop policy if exists "own enrollments" on public.enrollments;
create policy "own enrollments" on public.enrollments
  for all using (auth.uid() = user_id) with check (auth.uid() = user_id);

-- Create the profile automatically, for email and Google sign-ups alike
create or replace function public.handle_new_user()
returns trigger
language plpgsql
security definer set search_path = public
as $$
begin
  insert into public.profiles (id, name, email, ref)
  values (
    new.id,
    coalesce(new.raw_user_meta_data->>'name', new.raw_user_meta_data->>'full_name', split_part(new.email, '@', 1)),
    new.email,
    new.raw_user_meta_data->>'ref'
  )
  on conflict (id) do nothing;
  return new;
end;
$$;

drop trigger if exists on_auth_user_created on auth.users;
create trigger on_auth_user_created
  after insert on auth.users
  for each row execute function public.handle_new_user();
```

## 4. Google login

Google sign-in is already wired in the app (`Continue with Google` on
`/sign-in` and `/sign-up`, callback at `/auth/callback`). It needs three settings
before it will work.

### 4.1 Google Cloud Console

1. <https://console.cloud.google.com> → create or pick a project.
2. **APIs & Services → OAuth consent screen** → External → fill in app name
   (`CHRISCO Digital Academy`), support email and developer email → save.
   Add scopes `userinfo.email` and `userinfo.profile`.
3. **APIs & Services → Credentials → Create credentials → OAuth client ID**
   - Application type: **Web application**
   - Name: `CHRISCO Digital Academy web`
   - **Authorised JavaScript origins**
     - `https://chriscoyouthaflame2025@gmail.com` is not a URL, use your real domain
     - `https://your-production-domain.com`
     - `http://localhost:3000`
   - **Authorised redirect URI** (this is Supabase, not your site):
     - `https://YOUR-PROJECT-REF.supabase.co/auth/v1/callback`
4. Copy the **Client ID** and **Client secret**.

### 4.2 Supabase dashboard

1. **Authentication → Providers → Google** → toggle **Enable**.
2. Paste the Client ID and Client secret → **Save**.
3. **Authentication → URL Configuration**
   - **Site URL**: `https://your-production-domain.com`
   - **Redirect URLs**, add each of these:
     - `https://your-production-domain.com/auth/callback`
     - `http://localhost:3000/auth/callback`
     - `https://*.vercel.app/auth/callback` (for preview deployments)

If the redirect URL is not listed, Google sign-in returns to a blank page or
`/auth/callback` keeps waiting, which is the most common cause of "Google login
does not work".

### 4.3 Test it

1. Sign out, open `/sign-in`, click **Continue with Google**.
2. Choose an account; you should land on `/dashboard` with your name in the nav.
3. Check **Authentication → Users** in Supabase, the account should appear with
   provider `google`, and `profiles` should have a matching row (created by the
   trigger above).

## 5. Email sign-in notes

- For production, keep **Confirm email** on and set a custom SMTP provider
  (Authentication → Emails) so confirmation mails are not rate limited.
- For quick testing, turn **Confirm email** off so new accounts can sign in
  immediately.
- The contact address used across the site is
  `chriscoyouthaflame2025@gmail.com`; it is not an authentication address by
  itself, accounts are created in Supabase.
